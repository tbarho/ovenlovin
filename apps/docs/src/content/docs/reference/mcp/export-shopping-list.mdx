Export a shopping list for a saved meal plan with automatic ingredient aggregation, unit conversion, and per-person rule warnings. Supports multiple export formats for different use cases.

## Input Schema

| Parameter             | Type          | Required | Default      | Description                                                                     |
| --------------------- | ------------- | -------- | ------------ | ------------------------------------------------------------------------------- |
| `planId`              | string (UUID) | Yes      | -            | Meal plan ID to generate shopping list for                                      |
| `format`              | enum          | No       | `"markdown"` | Output format: `"json"`, `"csv"`, `"markdown"`, or `"text"`                     |
| `groupBy`             | enum          | No       | `"aisle"`    | Grouping strategy: `"aisle"`, `"recipe"`, or `"category"`                       |
| `includeStaples`      | boolean       | No       | `false`      | Include kitchen staples (salt, pepper, oil). Distinct from the pantry category. |
| `includePantryItems`  | boolean       | No       | - | Deprecated alias for `includeStaples`                                           |
| `includeRuleWarnings` | boolean       | No       | `true`       | Include per-person rule warnings for shoppers                                   |
| `timeZone`            | string        | No       | kitchen TZ   | IANA timezone for the markdown/text Generated line (always labeled)             |

## Output Schema

```typescript
{
  format: string,
  list: ShoppingListData, // structured object; never a JSON string
  content?: string,       // markdown / csv / text only; omitted for json
  itemCount: number,
  warnings: Array<{
    ingredient: string,
    personName: string,
    note: string
  }>
}
```

MCP `tools/call` also sets `structuredContent` to this object. Do not `JSON.parse` a string stuffed in `content` to get the list - read `structuredContent.list` (or `list` after one parse of the text JSON for `format: "json"`).

## Format Examples

### Markdown (default)

```markdown
# Shopping List

**Week Starting:** 2026-10-12
**Generated:** Oct 12, 2026, 4:00 PM CDT

## Produce

- [ ] 2 cups cherry tomatoes (Grilled Chicken Salad)
- [x] 1 head romaine lettuce (Grilled Chicken Salad)

## Meat

- [ ] 2 lbs chicken breast (Grilled Chicken Salad)

## Other

- [ ] paper towels

## ⚠️ Warnings

- **Child B**: parmesan cheese - Contains dairy (lactose intolerant preference)
```

## Grouping Strategies

### aisle

- Groups by grocery store aisle (produce, dairy, meat, etc.)
- Best for efficient shopping
- Kitchen staples land in a **Kitchen staples** section when `includeStaples` is true. That is not the pantry food-taxonomy category (flour, canned goods).

### recipe

- Groups by recipe
- Helps with recipe-by-recipe shopping
- Good for meal kit-style shopping

### category

- Groups by food taxonomy: produce, protein, dairy, grains, spices, pantry, frozen
- Distinct from aisle: chicken and salmon share **Protein** but sit in Meat vs Seafood aisles
- Balanced between organization and flexibility

## Usage Notes

1. **Automatic aggregation**: Duplicate ingredients across recipes are combined when possible
2. **Unit conversion**: Common unit conversions are applied (e.g., 3 tsp = 1 tbsp). Amounts follow the week cook-for; per-night servings do not change list amounts.
3. **Safety warnings**: Inline warnings alert shoppers to dietary restrictions and allergens
4. **Kitchen staples**: Enable `includeStaples: true` to include salt and oil. `includePantryItems` is still accepted as an alias. On each item, `isStaple` is canonical; `isPantryItem` is the same alias.
5. **Check-offs and extras**: Markdown uses `- [x]` for checked keys from the saved trip. Extras such as paper towels appear in `list` and in markdown/text/csv.
6. **Generated time**: The human-readable Generated line uses `timeZone` (IANA) and always includes a zone label such as CDT or UTC. `generatedAt` stays ISO-8601 UTC.
