OvenLovin REST at `/api/v1`. JSON bodies. OpenAPI 3.1 from the same Zod schemas the handlers use. All ids are UUIDs. `version` on `/health` is the API version (`0.1.0`), the same value as OpenAPI `info.version` and MCP `serverInfo.version`.

## Base URL

**Your instance**: `https://your-app.vercel.app/api/v1`

**Local Development**: `http://localhost:3000/api/v1`

## Authentication

Send `Authorization: ApiKey rkapi_...` or `Bearer` with the same key or a Clerk JWT. Clerk users must already have a kitchen (open the app once). On a Clerk JWT, optional `X-Kitchen-Id` selects a kitchen you belong to. An API key is bound to one kitchen; a mismatched `X-Kitchen-Id` is `403`.

No auth: `GET /health`, `GET /status`, `GET /openapi.json`, `GET /invites/{token}`.

```bash
curl -H "Authorization: Bearer <jwt-or-rkapi-key>" \
  https://your-app.vercel.app/api/v1/recipes
```

```bash
curl -H "Authorization: ApiKey <api-key>" \
  https://your-app.vercel.app/api/v1/recipes
```

Keys store `scopes`. A request outside the key's scopes returns `403` with `type` `<origin>/problems/forbidden`. The detail names the missing scope. Clerk sessions are not scope-checked. Omit scopes when you create a key for full access. `HEAD` is treated as `GET`.

`GET /api-keys`, `POST /api-keys`, and `DELETE /api-keys/{id}` are session-only. An API key gets `401`. `POST /api-keys` and `DELETE /api-keys/{id}` also require a signed-in admin or owner. The response field `plaintext` holds the full `rkapi_...` key. It is returned once.

Routes also authorize by kitchen membership role (viewer / member / admin / owner).

## Error Response (RFC 9457)

```json
{
  "type": "https://your-app.vercel.app/problems/validation-error",
  "title": "Validation Error",
  "status": 400,
  "detail": "Request validation failed",
  "instance": "https://your-app.vercel.app/api/v1/recipes",
  "errors": [
    {
      "path": "title",
      "message": "Invalid input: expected string, received undefined",
      "code": "invalid_type"
    }
  ]
}
```

`instance` is the full request URL. Non-JSON bodies are `400` `problems/bad-request` "Request body must be JSON".

Statuses the handlers return:

- `200` / `201` / `204` - Success, created (`Location` when set), no content
- `400` - Invalid input, including Zod validation (`problems/validation-error`)
- `401` - Missing or invalid auth
- `403` - Role not allowed, kitchen header mismatch, demo write/upload cap, or API key missing a required scope (`problems/forbidden`)
- `404` - Missing resource, unknown path, or a malformed or foreign id. Never `500`. Never another kitchen's data.
- `409` - Conflict (duplicate import, near-duplicate, in-flight import, household conflict)
- `410` - Expired invite
- `500` - Unhandled server error
- `503` - AI recipe reading is busy (`import_ai_unavailable`). `Retry-After: 60`

There is no rate limit today. Be gentle: retry `503` `import_ai_unavailable` after `Retry-After` seconds. The public demo can `403` writes after its sandbox cap.

`not_a_public_url` is an http(s) URL whose host is private, loopback, link-local, or not on port 80 or 443. Content that is not an http(s) URL at all (for example `file:` or `ftp:`) is `400` with detail "That doesn't look like a web address" and no `code`. Image fields otherwise: a public http(s) image URL, a stored blob URL, or an inline image.

## Idempotency-Key

Optional header. Any string (trimmed, first 512 characters). Not required to be a UUID.

Honored when saving a recipe: `POST /recipes`, `POST /recipes/import` with `save: true`, `POST /recipes/import/photo` with `save: true`. A completed key returns the first saved recipe (`200`). There is no "key conflict" status. `409` means a duplicate URL or photo, or an in-flight lock.

Other POSTs may read the header and ignore it.

## Pagination

```bash
GET /recipes?limit=20&cursor=<cursor-token>
```

`limit` defaults to `20` (`GET /cookbooks`: `50`). There is no maximum. `GET /cookbooks?view=cards` returns every cookbook in one page. Response: `{ items, nextCursor, hasMore }`. Rule and preference GETs return the array itself. `search` is a case-sensitive substring match on the title today.

## Endpoints

### Health

- `GET /health` - `{ status: "ok", version, timestamp }`. No auth. `version` is `0.1.0`.
- `GET /status` - No auth. `{ mode, commitSha, ready, checks }`
- `GET /openapi.json` - OpenAPI 3.1. No auth.

### Recipes

- `GET /recipes` - `limit`, `cursor`, `status` (`draft`, `needs_review`, `published`), `search` (title only; case-sensitive), `cookbookId`, `uncategorized=true`, `forAttendees` (person UUIDs, repeat or comma-separated). Blocked recipes land in `hidden`.
- `POST /recipes` - `{ title, ingredients: [{ rawText }], steps: [{ text }], ... }`. `201`, or `200` on idempotent replay
- `GET /recipes/{id}` - Details. Optional `?servings=`. `ingredients` are rows with `rawText` plus parsed `name`, `quantityMin`, `quantityMax`, `unit`. `steps` are rows with `text` and `order`.
- `PATCH /recipes/{id}` - Title, times, images, ingredients, steps, `cookbookIds`
- `DELETE /recipes/{id}` - `204`
- `POST /recipes/{id}/restore` - Undo a delete (`200` recipe)
- `GET /recipes/{id}/image` - `302` to the photo, or bytes when stored inline. `404` if none
- `POST /recipes/{id}/image` - `{ image: <data URL> }` (700KB max). `200` recipe
- `POST /recipes/import` - URL or paste. Preview unless `save: true`
- `POST /recipes/import/page` - Captured page `{ url, html?, jsonLd? }`. Saves. `201` (form post without JSON Accept: `303`)
- `POST /recipes/import/photo` - Photo. Preview unless `save: true`

Import failures: `400` with `not_a_public_url` (private/loopback http(s)), `import_blocked`, `import_page_private` (the page is private or needs a sign-in), `import_page_gone`, `import_not_a_recipe`, `import_unsupported_site`. Photo: `PHOTO_BLURRY`, `PHOTO_NOT_RECIPE`. `409` with `import_duplicate` (URL or exact photo already saved), `import_near_duplicate` (photo `save: true` without `allowDuplicate: true`), `import_in_progress` (same `Idempotency-Key` still running). Photo import on an instance without AI Gateway is `400` with no `code`. Busy model: `503` `import_ai_unavailable`.

There is no `POST /recipes/{id}/check`. To check one recipe for people, call `GET /recipes?forAttendees=<personId>` (blocked recipes are listed in `hidden`) or the MCP tool `get_recipe`.

### Cookbooks

- `GET /cookbooks` - default `limit` 50, no maximum. `?view=cards` returns every cookbook in one page (`recipeCount`, `previewImages`)
- `POST /cookbooks` - `{ name, description? }`
- `GET /cookbooks/{id}` / `PATCH /cookbooks/{id}` / `DELETE /cookbooks/{id}` (`204`)
- `POST /cookbooks/{id}/recipes` - `{ recipeId }`
- `DELETE /cookbooks/{id}/recipes?recipeId=`

### People and rules

- `GET /people` / `POST /people` - `{ displayName }`
- `GET /people/{id}` / `PATCH /people/{id}` / `DELETE /people/{id}` (mutate: admin)
- `POST /people/reorder` - `{ personIds }` (every person, once)
- `GET /people/{id}/rules` - Rule array
- `POST /people/{id}/rules` - `{ target, severity, kind?, note? }` (admin). `201` or `200` if duplicate
- `GET /people/{id}/rules/{ruleId}` / `PATCH` / `DELETE` (`204`)
- `GET /people/{id}/preferences?type=love` / `POST` / `GET .../{prefId}` / `DELETE`

### Meal plans

- `GET /meal-plans` - `limit`, `cursor`, `status`, `weekStart`, `weekEnd`
- `POST /meal-plans` - `{ weekStart, status?, entries? }`. `201` with the plan and `entries`. Entries come back with `mealSlot` (the `meal` you sent), `freeformMeal`, `scaleFactor`, and `attendees`.
- `GET /meal-plans/{id}` / `PATCH` / `DELETE` (`204`)
- `GET /meal-plans/{id}/check` - Run check (read only)
- `POST /meal-plans/{id}/check` - Run and persist (write). No body. Findings are `byEntry` and `byPerson`. If `status` is `incomplete`, do not treat the plan as safe.
- `POST /meal-plans/{id}/undo` / `GET /meal-plans/{id}/history`
- `GET /meal-plans/{id}/shopping-list` - `format`, `groupBy`, `includeStaples`, `timeZone`. JSON is `ShoppingListData` (`mealPlanId`, `weekStart`, `groupBy`, `includeStaples`, `includePantryItems`, `ingredients`, `sections`, `itemCount`, `generatedAt`, `warnings`, `scaledFor`, `scaledForMixed`). Section items use `key`, `name`, `quantity`, `unit`, `displayQuantity`, `displayUnit`, `aisle`, `category`, `isStaple`, `isPantryItem`, `recipes[]`, `checked`. Warnings are listed once in top-level `warnings`. A bad `timeZone` is `400`.
- `GET /meal-plans/{id}/shopping-list/state` / `PATCH` - `{ checkedKeys, extras }`

### Household

- `GET /households` / `PATCH /households` (owner, `{ name }`)
- `GET /households/mine` (API key: its one kitchen, `active: true`) / `POST /households/select` (signed-in only; API key `401`)
- `GET /households/settings` / `PATCH` - `{ mode: family|fixed|recipe, servings? }`
- `GET /households/schedule` / `PUT` - `{ week }`
- `GET /households/members` / `PATCH|DELETE /households/members/{userId}` (owner)
- `POST /households/leave` - signed-in only
- `GET|POST /households/invites` / `DELETE /households/invites/{id}` (admin; `200` with the revoked invite)
- `GET /invites/{token}` (no auth) / `POST /invites/{token}/accept` (signed-in)

There is no `GET /households/{id}/context`. `GET /households` returns the key's kitchen. `GET /people` lists people. `GET /people/{id}/rules` lists a person's rules. MCP `get_household_context` returns all of it in one call.

### Uploads and API keys

- `POST /uploads/images` - `file` or `{ url }`. `201` `{ url }`. Demo `403`
- `GET /api-keys` / `POST /api-keys` / `DELETE /api-keys/{id}` - signed-in only. An API key gets `401`. `POST` and `DELETE` also require admin or owner.

See [Kitchen invites](/docs/kitchen-invites).

This page lists common endpoints. The complete, current list is the OpenAPI spec at `/api/v1/openapi.json`.

## Multi-Tenant Security

Every query is filtered by the caller's household in application code. A malformed or foreign id on every `[id]` route returns `404`. Never `500`. Never another kitchen's data.
