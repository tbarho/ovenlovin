## Deploy to Vercel

The fastest way to get started is to deploy OvenLovin to Vercel with one click using the button above.

The one-click deploy will:

- Clone the repository to your GitHub account
- Create a new Vercel project
- Provision Neon Postgres, Vercel Blob, and Clerk (auto-configures `DATABASE_URL`, the blob token, and Clerk keys)
- Prompt for an optional instance name (USDA is optional; AI Gateway uses OIDC on Vercel)
- Run database migrations during the Vercel build
- Deploy the Next.js app

If the Clerk store is not offered, set `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` in the Vercel project.

## Local Development

### Prerequisites

- Node.js 20 or later
- pnpm 9 or later
- PostgreSQL database (or use Neon)

### Installation

OvenLovin is a pnpm workspace. Run `corepack enable` first; npm and yarn are not supported.

```bash
# Clone the repository
git clone https://github.com/tbarho/ovenlovin.git
cd ovenlovin

# Set up environment variables
cp .env.example apps/web/.env.local
# Edit apps/web/.env.local with your API keys

# Install dependencies
pnpm install

# Start Postgres (or use your own at the DATABASE_URL below)
docker compose -f docker-compose.e2e.yml up -d

# Run database migrations (reads DATABASE_URL from the shell, not .env.local)
export DATABASE_URL=postgresql://ovenlovin:ovenlovin@localhost:5432/ovenlovin
pnpm db:migrate

# Start development server
pnpm dev
```

The app will be available at `http://localhost:3000`.

### Development Commands

OvenLovin is a pnpm workspace. Run `corepack enable` first; npm and yarn are not supported.

```bash
# Run all workspaces in dev mode
pnpm dev

# Run specific workspace
pnpm --filter @ovenlovin/web dev
pnpm --filter @ovenlovin/core test:watch

# Build
pnpm build

# Test
pnpm test
pnpm test:watch

# Lint & format
pnpm lint
pnpm format
pnpm typecheck

# Clean
pnpm clean
```

## Talk to this instance

Send `Authorization: ApiKey rkapi_...` or `Bearer` with the same key or a Clerk JWT. Clerk users must already have an OvenLovin kitchen (open the app in the browser once; MCP does not create one). On MCP with a Clerk JWT, optional `X-Kitchen-Id` selects a kitchen you belong to. An API key is bound to one kitchen; a mismatched `X-Kitchen-Id` is rejected.

REST lives at `/api/v1`. Meal-plan checks are POST.

```bash
curl -H "Authorization: ApiKey YOUR_OVENLOVIN_API_KEY" \
  https://<your-app>.vercel.app/api/v1/recipes
```

```bash
curl -X POST \
  -H "Authorization: ApiKey YOUR_OVENLOVIN_API_KEY" \
  https://<your-app>.vercel.app/api/v1/meal-plans/PLAN_ID/check
```

MCP (Streamable HTTP):

```json
{
  "mcpServers": {
    "ovenlovin": {
      "url": "https://<your-app>.vercel.app/mcp",
      "headers": {
        "Authorization": "ApiKey YOUR_OVENLOVIN_API_KEY"
      }
    }
  }
}
```
