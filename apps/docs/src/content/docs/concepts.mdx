## Households

A **household** is the top-level entity in OvenLovin. It represents a family or group of people who share meals. Households are implemented as Clerk Organizations, providing:

- Multi-user access control
- Role-based permissions (admin, member)
- Invitation and member management

Each household can have:

- Multiple people with dietary rules
- A library of recipes
- Meal plans
- Shopping lists

## People

**People** are members of a household. Each person can have:

- Name and basic profile information
- Age (for age-appropriate meal suggestions)
- Activity level (affects nutritional recommendations)
- **Dietary rules** with severity levels

### Example People

```typescript
{
  id: "person_1",
  householdId: "household_1",
  name: "Parent A",
  rules: [
    {
      kind: "allergen",
      value: "peanuts",
      severity: "block",
      reason: "Severe peanut allergy"
    }
  ]
}
```

## Dietary Rules

Dietary rules are **per-person** configurations that define allergies, restrictions, and preferences. Each rule has:

### Rule Kinds

> **Note:** All rules are per-person and configured by the family admin. OvenLovin never hard-codes allergen policies.

- **allergen** - Food allergies (peanuts, tree nuts, dairy, eggs, fish, shellfish, wheat, soy, sesame)
- **ingredient** - Specific ingredient restrictions (garlic, onions, nightshades)
- **dietary** - Dietary patterns (vegetarian, vegan, gluten-free, kosher, halal)
- **nutrition** - Nutritional constraints (low-sodium, low-sugar, low-carb)

### Severity Levels

Each rule has a severity level that determines how strictly it's enforced:

| Severity | Meaning | Example |
|----------|---------|---------|
| `block` | Recipe is unsafe for this person | Severe peanut allergy |
| `warn` | Recipe should be flagged for review | Possible cross-contamination with allergen |
| `prefer_avoid` | Recipe is not preferred but not dangerous | Dietary preference, mild intolerance |

### Shared Facility Setting

Rules can include a `sharedFacility` flag to warn about products processed in facilities that also handle allergens:

```typescript
{
  kind: "allergen",
  value: "peanuts",
  severity: "warn",
  sharedFacility: true,
  reason: "Warn if processed in facility with peanuts"
}
```

## Recipes

Recipes are the building blocks of meal plans. Each recipe includes:

- **Basic info** - Title, description, source URL
- **Ingredients** - List with quantities and units
- **Instructions** - Step-by-step directions
- **Nutrition** - Calories, macros, vitamins (from USDA FoodData Central)
- **Metadata** - Servings, prep time, cook time, cuisine, dietary tags

### Recipe Import

OvenLovin supports multiple import methods:

- **URL Import** - Import from recipe websites with AI-powered extraction
- **Photo/OCR** - Take a photo of a recipe card or cookbook page
- **Voice Input** - Dictate a recipe to your AI agent
- **Paste/Text** - Copy and paste recipe text from any source

### Example Recipe

```json
{
  "id": "recipe_1",
  "title": "Chocolate Chip Cookies",
  "ingredients": [
    {
      "name": "all-purpose flour",
      "quantity": { "min": 2.5, "max": 2.5 },
      "unit": "cups"
    },
    {
      "name": "butter",
      "quantity": { "min": 1, "max": 1 },
      "unit": "cup"
    },
    {
      "name": "chocolate chips",
      "quantity": { "min": 2, "max": 2 },
      "unit": "cups"
    }
  ],
  "nutrition": {
    "servings": 24,
    "caloriesPerServing": 150
  }
}
```

## Meal Plans

A **meal plan** organizes recipes into a schedule with attendees and rule checking. Each meal plan includes:

- **Date range** - Start and end dates
- **Meals** - Breakfast, lunch, dinner, snacks for each day
- **Attendees** - Which household members will eat each meal
- **Rule check results** - Per-person findings with severity

### Meal Plan Checking

> **Warning:** Safety-critical: Rule checking is **deterministic** for the same inputs (recipe, attendees, rules) and always names the affected person.

When you check a meal plan, OvenLovin:

1. Loads all recipes in the plan
2. Loads all attendees and their dietary rules
3. Checks each recipe against each attendee's rules
4. Returns per-person findings with severity

### Check Status

- `complete` - All checks passed successfully
- `incomplete` - Checking could not complete (reasons provided)
- Never returns "no issues" when checking cannot complete

### Example Findings

```json
{
  "status": "complete",
  "findings": {
    "block": [
      {
        "personId": "person_1",
        "personName": "Parent A",
        "severity": "block",
        "recipeId": "recipe_1",
        "recipeName": "Peanut Butter Cookies",
        "ingredientName": "peanut butter",
        "reason": "Parent A: recipe contains peanut butter (block rule for peanuts)"
      }
    ],
    "warn": [],
    "preferAvoid": []
  }
}
```

## Shopping Lists

Shopping lists aggregate ingredients from a meal plan and organize them by grocery store section. Each shopping list includes:

- **Aggregated quantities** - Combined amounts for the same ingredient
- **Unit conversions** - Standardized units (metric/US)
- **Allergen warnings** - Flagged ingredients based on dietary rules
- **Store sections** - Produce, dairy, meat, pantry, frozen, etc.

### Example Shopping List

```json
{
  "id": "list_1",
  "mealPlanId": "plan_1",
  "items": [
    {
      "ingredient": "all-purpose flour",
      "quantity": { "min": 5, "max": 5 },
      "unit": "cups",
      "section": "pantry",
      "warnings": []
    },
    {
      "ingredient": "peanut butter",
      "quantity": { "min": 2, "max": 2 },
      "unit": "cups",
      "section": "pantry",
      "warnings": [
        {
          "personName": "Parent A",
          "severity": "block",
          "reason": "Parent A has a block rule for peanuts"
        }
      ]
    }
  ]
}
```

## Safety Invariants

> **Critical:** These invariants are **safety-critical** and must never be broken:

1. **Rule checking is deterministic** for the same inputs (recipe, attendees, rules)
2. **Warnings name the affected person** and are returned in every relevant API response
3. **Recipe edits or rule changes mark affected plans as `needs_recheck`**
4. **Incomplete checks are reported as `status: incomplete`**, never "no issues"
5. **No hard-coded allergen policies** - all rules are per-person config set by the family admin
